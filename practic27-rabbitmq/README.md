## 1. Описание реализации
В рамках данного практического занятия реализована система асинхронной обработки задач с использованием RabbitMQ. Приложение состоит из API-сервиса (Producer), который принимает задачи, и набора воркеров (Consumers), которые их обрабатывают.

Реализованы механизмы надежности:
- **Retry Logic:** При ошибке обработки задача возвращается в очередь с экспоненциальной задержкой (до 3 попыток).
- **Dead Letter Queue (DLQ):** Задачи, не обработанные после максимального числа попыток, перемещаются в отдельную очередь для ручного анализа.
- **Load Balancing:** Задачи распределяются между несколькими запущенными воркерами (Round Robin).

## 2. Инструкция по запуску

### Требования
- Node.js (v16+)
- Docker (для RabbitMQ)

### Шаг 1: Запуск RabbitMQ
```bash
docker run -d --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:3-management
```

### Шаг 2: Установка зависимостей
```bash
npm install
```

### Шаг 3: Запуск Producer (API)
```bash
node producer.js
```

### Шаг 4: Запуск Workers
Запустите в отдельных терминалах для демонстрации распределения нагрузки:
```bash
# Терминал 1
WORKER_ID=1 node worker.js

# Терминал 2
WORKER_ID=2 node worker.js
```

## 3. Тестирование

### Создание задачи
```bash
curl -X POST http://localhost:3000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"type": "email", "payload": {"to": "user@example.com"}}'
```

### Проверка отказоустойчивости
Для имитации ошибки используйте тип задачи `"fail"`:
```bash
curl -X POST http://localhost:3000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"type": "fail", "payload": {}}'
```
В логах воркера будет видно 3 попытки обработки с задержками, после чего задача переместится в DLQ.
